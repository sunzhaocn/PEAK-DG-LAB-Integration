# Coyote 图形化规则使用说明

## 1. 规则系统定位

自定义规则已经从“用户编写 Python 脚本”改为 **模块 + 端口 + 连线** 的图形化节点规则。

规则保存在：

```text
Coyote/visual_rules.json
```

程序本体仍然使用 PySide6 / Python，不需要额外安装 Unity。这里借鉴的是 Unity Shader Graph / Unreal Blueprint 的节点编辑方式，而不是把整个桌面程序改成 Unity 工程。

图形规则文件本身是 JSON 数据，不执行用户 Python 代码。

---

## 2. 最重要的原则：官方规则与自定义规则完全分开

从当前版本开始，必须把下面两套系统理解成两个独立规则域：

| 规则域 | 配置来源 | 死亡/昏迷保护 | 是否受“禁用软件内置规则”影响 |
|---|---|---|---|
| 官方规则 | 原软件规则页面 | 使用官方自己的死亡/昏迷逻辑 | 是 |
| 自定义图形规则 | 图形化规则页面 | **默认没有**，需要用户自己加保护模块 | 否 |

也就是说：

- 自定义规则不会自动继承官方规则的“死亡/昏迷后禁止电击”；
- 自定义规则不会自动继承官方死亡/昏迷电击规则；
- 自定义死亡规则和官方死亡规则是两套独立规则；
- 自定义昏迷规则和官方昏迷规则也是两套独立规则；
- 当官方规则没有被禁用时，官方规则与自定义规则可以同时启用、同时满足条件、分别输出；
- 不再因为存在自定义死亡图，就自动关闭官方死亡规则；
- 不再因为存在自定义昏迷图，就自动关闭官方昏迷规则。

共享的只是底层设备基础设施，例如：

- DG-LAB 设备连接；
- A/B 通道；
- 总输出开关；
- 强度硬上限；
- 立即停止；
- 断开设备；
- 程序退出时的设备处理。

这些属于设备层，不属于“官方规则”或“自定义规则”的业务规则。

---

## 3. 基本操作

1. 打开侧栏 **图形化规则**。
2. 在左侧模块库双击模块。
3. 在中间画布拖动模块排版。
4. 点击源模块右侧输出端口，再点击目标模块左侧输入端口完成连线。
5. 选中模块，在右侧修改属性。
6. 点击 **应用属性**。
7. 勾选 **启用当前图**。
8. 点击 **校验并保存**。

快捷操作：

- `Delete / Backspace`：删除选中的模块或连线；
- 鼠标滚轮：缩放画布；
- 框选：同时选择多个模块；
- 一张图可以存在多个电击输出节点。

## 4. “禁用软件内置规则”现在的准确含义

把 **禁用软件内置规则** 模块放入任意一张 **已启用且校验通过的普通图** 后，它作为全局接管开关生效，不需要连线。

生效后，关闭的是 **整个官方自动规则域**，包括：

- 官方血量规则；
- 官方体力规则；
- 官方速度规则；
- 官方跳跃 / 攀爬 / 蹲下规则；
- 官方物品规则；
- 官方状态规则；
- 官方区域规则；
- 官方死亡电击规则；
- 官方昏迷电击规则；
- 官方“角色死亡/昏迷后清除输出”的规则级保护逻辑。

因此：

> 开启“禁用软件内置规则”以后，不会偷偷保留官方死亡/昏迷电击，也不会偷偷保留官方死亡/昏迷保护。

这时自定义图形规则是否在死亡/昏迷后继续输出，只由自定义图自己决定。

### 仍然保留的东西

下面这些不是官方自动规则，所以不会因为“禁用软件内置规则”而失效：

- 总输出开关；
- 设备连接检查；
- 强度硬上限；
- 立即停止；
- 设备断开；
- 程序退出处理。

## 5. 自定义规则保护模块

左侧新增分类：

```text
自定义规则保护
```

里面有三个模块：

### 未死亡保护（仅自定义）

输出条件为：

```text
dead == false
```

角色一旦死亡，该模块输出 `False`。

### 未昏迷保护（仅自定义）

输出条件为：

```text
passedOut == false
```

角色一旦昏迷，该模块输出 `False`。

### 存活且清醒保护（仅自定义）

等价于：

```text
not dead AND not passedOut
```

死亡或昏迷任意一个成立时，该模块都会输出 `False`。

### 如何使用

例如你有一条自定义速度规则：

```text
速度高于阈值 ──────────────┐
                           ├──> 电击输出
存活且清醒保护（仅自定义） ─┘
```

`电击输出.in` 可以接多个条件，当前执行逻辑要求这些条件全部为真，所以这里不一定需要额外放 AND 节点。

如果你 **不接任何自定义保护模块**，那么自定义图形规则不会因为角色死亡/昏迷而自动被官方保护锁拦截。

这就是当前版本的明确设计。

---

## 6. 死亡 / 昏迷自定义电击

死亡和昏迷仍然提供两个专用触发模块：

- **死亡（专用）**；
- **昏迷（专用）**。

它们属于 **自定义规则域**，不是官方规则的副本。

推荐分别建立两张图：

```text
死亡（专用）
    ↓
强度 / 持续时间 / 波形
    ↓
电击输出
```

以及：

```text
昏迷（专用）
    ↓
强度 / 持续时间 / 波形
    ↓
电击输出
```

### 为什么仍然要求分开

死亡和昏迷是两个不同状态边沿。为了避免一张特殊图里混入多种语义导致难以判断优先级，校验器仍然要求：

- 死亡图和昏迷图分开；
- 一张特殊图只允许一种专用触发器；
- 特殊图不能混入普通规则事件；
- 特殊图不能混入普通遥测 / 物品 / 比较逻辑；
- `禁用软件内置规则` 不能放在特殊图里。

“禁用软件内置规则”只需要存在于任意一张启用的普通图中，就会全局关闭官方规则域。

---

## 7. 官方死亡规则与自定义死亡规则不会互相替代

当前语义如下：

### 情况 A：官方规则没有禁用

如果：

- 官方“死亡电击”开启；
- 自定义“死亡（专用）”图也开启；

那么两套规则都可以触发。

不会因为自定义死亡图存在，就自动把官方死亡规则当成 fallback 关闭。

昏迷同理。

### 情况 B：存在“禁用软件内置规则”模块

这时：

- 官方死亡电击不触发；
- 官方昏迷电击不触发；
- 官方死亡/昏迷后的规则级清输出保护不执行；
- 自定义死亡图是否触发由自定义图决定；
- 自定义昏迷图是否触发由自定义图决定；
- 其他自定义规则是否继续运行也由自定义图自己的条件决定。

---

## 8. 自定义规则默认可以在死亡/昏迷状态继续执行

旧实现曾经在自定义发送路径里直接检查：

```text
peak_is_incapacitated()
```

只要当前死亡或昏迷，就把普通图形规则直接拦截。

这个逻辑已经取消。

现在图形规则的判断流程是：

```text
读取当前遥测
    ↓
计算自定义图节点
    ↓
只看自定义图自己的条件是否满足
    ↓
满足则进入自定义输出
```

不会再额外插入：

```text
“因为官方认为角色死亡/昏迷，所以禁止这个自定义规则”
```

如果你需要这种行为，必须自己加入第 5 节的保护模块。

## 9. 当前软件规则事件模块

“当前软件全部规则事件”由运行时 `B.RULE_META` 动态生成，而不是人工写死。

目前包括现有规则系统中的主要事件：

### 生命 / 状态

- 血量下降；
- Injury / Hunger / Cold / Poison / Crab / Curse / Drowsy / Weight / Hot / Thorns / Spores / Web / Arrow / Petrify / FlyTrap；
- 血量恢复；
- 体力恢复；
- 状态恢复。

### 动作 / 运动

- 体力消耗；
- 速度低于阈值；
- 速度高于阈值；
- 跳跃；
- 开始攀爬；
- 蹲下。

### 物品

- 拿起手持物；
- 背包装入物品；
- 当前手持匹配物品；
- 背包存在匹配物品；
- 食用 / 消耗物品。

### 区域

- 进入区域；
- 区域停留。

死亡 / 昏迷不通过普通 `trigger` 冒充，使用专用死亡 / 昏迷模块。

## 10. 事件检测参数

图形事件节点可以携带原有检测器需要的参数：

| 事件节点 | 节点参数 |
|---|---|
| 体力消耗 | `trigger_delta` |
| 速度低于 / 高于阈值 | `speed_threshold` |
| 手持 / 背包 / 状态型物品 | `item_filter` |
| 食用 / 消耗物品 | `item_filter` |
| 血量恢复 / 体力恢复 | `trigger_delta`、`trigger_mode` |
| 状态恢复 | `trigger_delta` |
| 进入区域 | `area_zones` |
| 区域停留 | `area_zones`、`area_dwell_seconds`、`trigger_mode` |

当官方规则被禁用时，软件仍可以临时复用现有检测器来给图形事件节点提供“事件是否发生”的结果。

这里复用的是 **检测代码**，不是复用官方规则输出。

处理过程是：

```text
只为图中实际使用的事件临时打开检测器
    ↓
读取节点自己的阈值 / 筛选参数
    ↓
记录事件是否发生
    ↓
官方规则输出在接管门被拦截
    ↓
恢复旧规则真实配置
```

因此“复用官方检测器”不等于“官方规则仍然生效”。

## 11. 数据 / 条件模块

当前支持：

- **遥测字段**：读取 `hp`、`speed`、`climbing`、`position.x` 等；
- **状态百分比**；
- **物品匹配**；
- **字段变化**；
- **常量**；
- **比较**：`>`、`>=`、`<`、`<=`、`==`、`!=`、`contains`；
- **AND / OR / NOT**；
- **上升沿 / 持续**；
- **冷却**；
- **自定义规则保护**。

示例：

```text
遥测字段(speed)
       ↓ a
    比较(> 6)
       ↓
    上升沿
       ↓
    电击输出
```

## 12. 输出参数模块

### 强度

支持：

- A/B 基础强度；
- A/B 最大强度；
- 随机强度；
- 随机强度上下限；
- 强度渐升；
- 渐升时间；
- 渐升步数。

### 关于死亡/昏迷时的渐升

现有渐升执行器内部原本带有官方 incapacitated 检查。

为了保证“自定义规则不继承官方死亡/昏迷保护”，当前处理为：

- 正常状态：自定义规则可以继续复用现有渐升执行器；
- 死亡/昏迷状态：如果自定义图仍然允许输出，则改为直接发送目标强度，不让旧渐升线程把自定义输出取消。

### 持续时间

- A/B 独立；
- `-1` 表示条件成立期间持续续播；
- 底层仍发送有限片段。

### 波形

- A/B 独立；
- 使用当前软件波形库；
- 支持已加载的自定义波形。

### 百分比档位

连接到输出 `modifier`，并把参与判断的百分比接到输出 `value`。

### 瞬时变化加强

连接到 `modifier`，变化量接到输出 `delta`。

### 随机波形

连接到 `modifier`，从指定波形池中随机选择。

### 电击输出

支持：

- `mode=edge`；
- `mode=while`；
- `mode=repeat`；
- `cooldown`。

持续规则继续复用 `continuous_effective_cooldown()` 计算有效冷却。

## 13. 三个典型配置

### 方案 1：完全接管官方规则，但死亡后仍允许自定义规则继续

```text
图 A：
禁用软件内置规则

图 B：
速度高于阈值 → 电击输出
```

这里没有加入任何自定义保护，因此官方死亡保护已经关闭，自定义图是否继续满足条件由图本身决定。

### 方案 2：完全接管官方规则，并要求所有普通自定义规则在死亡/昏迷后停止

```text
图 A：
禁用软件内置规则

图 B：
速度高于阈值 ──────────────┐
                           ├──> 电击输出
存活且清醒保护（仅自定义） ─┘
```

其他需要保护的自定义输出也要自己连接保护模块。

### 方案 3：死亡时使用一条自定义专用电击

```text
普通图：
禁用软件内置规则

死亡专用图：
死亡（专用） → 强度 → 持续时间 → 波形 → 电击输出
```

因为官方规则已经被禁用，所以此时只执行你自己配置的死亡专用图。

## 14. 旧 Python 自定义规则

旧 `.py` 自定义规则文件不会强制删除，方便备份或人工迁移。

但是新版入口不再把它们作为活动的用户规则系统：

- 不再要求用户写 Python；
- 不再从图形化规则页面导入 Python 自定义规则；
- 新规则使用 `visual_rules.json`。

---

## 15. 仍然需要注意的底层边界

“官方规则与自定义规则分开”指的是 **规则语义和规则开关分开**。

DG-LAB 仍然只有实际设备通道，所以以下设备级动作天然会影响当前设备输出：

- 用户主动点击立即停止；
- 关闭总输出；
- 设备断开；
- 程序关闭；
- 底层连接失败。

这些不是官方死亡保护，也不会被“禁用软件内置规则”绕过。

---

## 16. 推荐配置方式

如果你想把规则完全交给图形化系统：

1. 新建普通图；
2. 放入 **禁用软件内置规则**；
3. 建立需要的普通自定义图；
4. 决定这些图是否需要死亡保护、昏迷保护或“存活且清醒保护”；
5. 需要保护就显式把保护模块连到对应输出；
6. 需要死亡触发电击时，单独建立 **死亡（专用）** 图；
7. 需要昏迷触发电击时，单独建立 **昏迷（专用）** 图；
8. 校验并保存；
9. 先观察事件日志；
10. 确认逻辑无误后再打开总输出。

核心原则只有一句：

> **官方规则负责官方规则，自定义规则负责自定义规则；禁用官方规则以后，官方死亡/昏迷保护也一起消失，自定义规则需要的保护必须由自定义图自己明确添加。**
