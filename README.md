Coyote 软件功能与配置说明

1. 软件简介

Coyote 是一套面向 PEAK 游戏状态联动与 DG-LAB 设备控制的桌面应用程序。

软件通过 PEAK 游戏侧的 BepInEx 插件采集玩家实时状态，并将状态数据发送至 Coyote 桌面端。桌面端依据用户预先配置的规则，对血量、体力、寒冷、中毒、石化等状态变化进行判断，并通过 DG-LAB WebSocket 服务执行对应的设备反馈逻辑。

Coyote 主要由以下模块组成：

PEAK 游戏插件

基于 C# / BepInEx

负责游戏状态采集与数据传输

Coyote 桌面客户端

基于 Python / PySide6

负责状态显示、规则管理、设备控制、日志记录及配置管理

DG-LAB WebSocket 服务

基于 Bun / TypeScript

负责桌面端与 DG-LAB 相关设备之间的通讯

2. 核心功能

2.1 游戏状态实时监测

Coyote 可持续接收 PEAK 游戏插件发送的玩家状态数据，并在桌面客户端中进行实时展示与规则判断。

支持监测的状态包括但不限于：

当前血量

当前体力

寒冷状态

中毒状态

受伤状态

石化状态

其他可读取的 PEAK 状态值

玩家死亡状态

玩家昏迷状态

实际可读取的状态项目取决于当前 PEAK 游戏版本及插件兼容情况。

2.2 自动规则系统

Coyote 提供基于游戏状态变化的自动规则系统。

每一项状态均可独立配置规则，例如：

血量降低时触发

体力降低时触发

寒冷值增加时触发

中毒值增加时触发

石化值增加时触发

指定状态达到阈值后持续触发

每条规则均可独立启用或停用。

规则配置可包含：

触发条件

A 通道强度

B 通道强度

随机强度范围

单次反馈

持续反馈

持续时间

触发阈值

强度上限

优先级

瞬时变化加强

自定义加强档位

3. 强度配置

3.1 固定强度

当规则设置为固定强度时，每次触发均使用相同的目标值。

示例：

A 通道：30
B 通道：20

规则触发后将按设定值执行。

3.2 随机强度

Coyote 支持为 A、B 通道分别配置随机范围。

示例：

A 通道：20 ~ 40
B 通道：10 ~ 30

每次规则触发时，系统会在对应范围内生成一次随机值。

例如：

第一次：
A = 27
B = 16

第二次：
A = 38
B = 24

随机强度用于减少重复触发时反馈完全一致的情况。

3.3 最大强度限制

每条规则可设置 A、B 通道允许达到的最大强度。

即使随机强度或瞬时变化加强产生更高数值，最终结果仍应受到规则最大强度和程序内部安全限制约束。

建议根据设备实际情况合理设置最大值。

4. 瞬时大变化加强

4.1 功能说明

Coyote 可以检测某一状态在单次采样周期内发生的明显变化，并根据变化幅度附加额外强度。

系统判断依据为：

本次状态变化量

而不是变化后的最终状态值。

例如血量变化：

原始状态

当前状态

单次变化量

100

90

10

100

80

20

100

50

50

100

25

75

100

0

100

因此：

100 → 25

对应的瞬时变化量为：

75

4.2 自定义档位

用户可以根据需要添加任意数量的瞬时变化档位。

示例：

单次变化至少

A 通道额外值

B 通道额外值

20

+5 ~ +10

+5 ~ +10

40

+10 ~ +20

+10 ~ +25

60

+20 ~ +40

+20 ~ +50

80

+40 ~ +70

+40 ~ +80

所有阈值与附加强度范围均可自行调整。

例如可自行定义：

变化 ≥ 15
变化 ≥ 30
变化 ≥ 55
变化 ≥ 75
变化 ≥ 90

系统不限制必须使用固定的 20 / 50 / 80 档位。

4.3 档位匹配逻辑

当一次状态变化同时满足多个档位时：

系统仅应用满足条件的最高档位。

例如：

档位 1：变化 ≥ 20
档位 2：变化 ≥ 50
档位 3：变化 ≥ 75

如果本次变化量为：

80

则仅应用：

变化 ≥ 75

这一档位。

不会同时叠加 20、50、75 三个档位。

这样可避免多档重复累加造成异常强度。

4.4 固定附加强度

如果希望某个档位使用固定附加值，可将最小值与最大值设置为相同数值。

例如：

A：30 ~ 30
B：40 ~ 40

表示：

A 固定额外增加 30
B 固定额外增加 40

5. 状态恶化与状态恢复

瞬时变化加强主要用于识别状态恶化。

例如：

血量 100 → 30

属于明显恶化，可参与瞬时变化加强判断。

而：

血量 30 → 100

属于恢复。

对于恢复方向，系统原则上仅记录状态变化，不应按照恶化规则追加惩罚。

相同逻辑适用于：

寒冷降低

中毒恢复

石化恢复

其他 Debuff 状态恢复

6. 单次反馈与持续反馈

6.1 单次反馈

单次反馈适用于发生一次明确事件时立即触发。

例如：

血量突然下降 50

可触发一次指定强度和持续时间的反馈。

6.2 持续反馈

持续反馈适用于某项状态长期处于指定范围。

例如：

寒冷值持续高于设定阈值

可持续执行对应规则。

6.3 优先级机制

为防止持续规则覆盖高优先级的单次事件，Coyote 提供规则优先级控制。

默认设计原则为：

单次事件优先于持续状态。

典型流程：

重大状态变化
↓
触发单次规则
↓
单次规则进入有效窗口
↓
持续规则暂时让位
↓
单次规则结束后恢复持续规则判断

用户可根据实际需求调整规则优先级。

7. 死亡 / 昏迷保护

7.1 功能说明

Coyote 提供死亡和昏迷状态保护。

当系统检测到玩家已经：

死亡

或：

昏迷

时，会阻止普通自动规则继续执行。

主要用于避免以下情况：

玩家死亡
↓
寒冷 / 中毒 / 其他 Debuff 仍继续变化
↓
状态规则继续触发
↓
产生不必要的持续反馈

7.2 安全锁逻辑

进入死亡 / 昏迷状态后，系统应优先执行安全锁逻辑：

阻止新的自动规则触发

停止普通持续反馈

清除正在执行的自动规则状态

避免 Debuff 在死亡后继续引发反馈

此机制优先级高于普通游戏状态规则。

8. 石化状态检测

PEAK 游戏更新后，部分状态在内部状态数组中的顺序可能发生变化。

为降低固定下标失效造成的识别错误，Coyote 对石化状态采用多层兼容读取方式。

主要策略包括：

优先读取 PEAK 当前状态系统

尝试根据状态名称匹配

使用游戏状态接口获取当前值

必要时使用兼容回退逻辑

该机制主要用于减少：

游戏中石化值已经发生变化
但 Coyote 始终显示 0

的情况。

具体兼容效果仍取决于 PEAK 当前游戏版本。

9. 批量规则配置

Coyote 支持对多个规则执行批量参数应用。

用户可先勾选目标规则，再通过批量应用功能统一修改配置。

适合批量调整的参数包括：

A 通道强度

B 通道强度

随机范围

持续时间

最大强度

优先级

启用状态

其他通用规则参数

批量设置可减少大量重复配置操作。

14. 推荐配置流程

首次使用建议按照以下顺序完成配置。

第一步：确认游戏环境

确认：

PEAK

已经安装并可正常启动。

第二步：确认 BepInEx

游戏目录中应存在：

BepInEx

例如：

PEAK/
└─ BepInEx/
   ├─ core/
   ├─ plugins/
   └─ config/

第三步：安装 Coyote.dll

将编译得到的：

Coyote.dll

安装至：

PEAK\BepInEx\plugins\Coyote.dll

实际路径根据 PEAK 安装位置确定。

第四步：配置 Bun

将：

bun.exe

放到：

Coyote\dglab-websocket-server-main\bun.exe

第五步：启动 Coyote

启动：

Coyote.exe

或者从源码启动：

cd Coyote

python -m pip install -r requirements.txt

python main.py

第六步：启动 WebSocket 服务

根据程序当前设计，由 Coyote 自动或手动启动对应 WebSocket 服务。

服务器文件通常包括：

v3-server.ts
v4-server.ts

第七步：连接设备

完成 DG-LAB 相关设备或控制端连接。

确认客户端中 WebSocket 状态正常。

第八步：启动 PEAK

进入游戏后，确认 Coyote 能够接收到：

血量

体力

状态值

死亡 / 昏迷状态

第九步：配置规则

建议从较低强度开始配置。

推荐流程：

启用单条规则
↓
设置较低强度
↓
进入游戏测试
↓
确认触发逻辑正确
↓
逐步增加强度
↓
再启用更多规则

15. 规则配置建议

15.1 血量规则

适用于：

血量降低

建议配置：

单次触发

根据掉血幅度调整强度

启用瞬时大变化加强

高优先级

例如：

小幅掉血 → 低强度
中等掉血 → 中强度
大量掉血 → 高强度
瞬间大幅掉血 → 额外加强

15.2 寒冷规则

寒冷属于较典型的持续状态。

建议：

使用持续反馈

设置合理触发阈值

优先级低于重大单次事件

配合死亡 / 昏迷保护使用

15.3 中毒规则

中毒通常具有持续变化特点。

可根据：

中毒值

中毒增长速度

持续时间

设置对应规则。

15.4 石化规则

石化状态可能受到游戏版本影响。

建议首次使用时观察：

状态显示

和：

日志

确认石化数值是否正常变化后，再配置自动规则。

20. 软件设计原则

Coyote 的规则系统设计目标为：

将游戏状态变化转换为可配置、可分级、可管理的反馈事件。

系统并非简单采用：

状态变化 = 固定反馈

而是综合考虑：

当前状态

状态变化方向

单次变化幅度

规则优先级

随机强度

最大强度

持续状态

玩家死亡 / 昏迷状态

自定义加强档位

从而实现较细粒度的规则控制。

21. 使用安全说明

本项目涉及外部硬件反馈设备。

用户应遵守相关设备厂商的安全说明，并根据自身情况合理配置参数。

软件中的以下参数：

最大强度
随机范围
持续时间
瞬时加强

属于软件层面的逻辑控制，不应视为硬件安全保护的替代方案。

建议：

首次使用时从较低强度开始

修改规则后先进行低强度测试

避免一次性设置过高的最大值

避免持续时间过长

确认死亡 / 昏迷保护正常工作

确认设备本身的安全限制已启用
