# Coyote 软件介绍

## PEAK × DG-LAB 图形化联动工具

Coyote 是一个连接 **PEAK 游戏遥测系统与 DG-LAB 设备** 的桌面联动工具。

程序通过 BepInEx / Coyote.dll 读取 PEAK 的实时状态，再由桌面端完成规则判断、DG-LAB V4 通信、多人设备路由和输出控制。

---

# 1. 实时游戏状态

Coyote 可以读取并展示：

- 血量、体力、额外体力；
- 死亡、昏迷；
- 攀爬、接地、蹲下、跳跃；
- 速度、位置和运动信息；
- 当前手持物、口袋、背包；
- 最近使用 / 食用 / 消耗物品；
- Injury、Hunger、Cold、Poison 等异常状态；
- 场景、关卡与运行时扩展字段；
- 多人联机玩家遥测。

---

# 2. DG-LAB 控制

Coyote 支持：

- DG-LAB APP 扫码配对；
- A/B 通道独立控制；
- 多种内置和自定义波形；
- 有限持续时间和 `-1` 条件持续语义；
- 多设备管理；
- 多人玩家与设备绑定；
- 一键立即停止；
- 总输出开关。

强度数字表示 DG-LAB 协议等级，不代表实际 mA。

---

# 3. 官方内置规则

当前官方规则系统覆盖：

- 血量下降；
- 死亡；
- 昏迷；
- 体力消耗；
- 速度高于 / 低于阈值；
- 跳跃、开始攀爬、蹲下；
- 手持物与背包物品；
- 当前手持 / 背包状态；
- 全部异常状态；
- 食用 / 消耗物品；
- 血量、体力、异常状态恢复；
- 进入区域、区域停留；
- 随机波形；
- 受伤后强度渐升；
- 百分比档位；
- 瞬时大变化加强。

官方规则仍可以单独使用。

图形规则可以复用其中的“事件检测器”获得事件边沿，但这只是复用检测代码，不代表图形规则属于官方规则系统。

---

# 4. 图形化自定义规则

自定义规则不再要求用户编写 `.py`。

新版规则编辑方式参考 Unity Shader Graph / Unreal Blueprint：

```text
事件 / 数据模块
      ↓
比较 / AND / OR / NOT
      ↓
边沿 / 冷却
      ↓
强度 / 持续时间 / 波形 / 动态档位
      ↓
电击输出
```

用户在软件内拖动模块并通过端口连线组成规则，规则保存到：

```text
Coyote/visual_rules.json
```

规则文件是普通 JSON，不执行用户代码，也不给规则文件系统、网络或命令执行权限。

### 图形模块覆盖

模块库会从运行时 `RULE_META` 动态生成“当前软件全部规则事件”，因此已注册的基础规则和 `extended_features.py` 扩展规则都可以直接作为事件模块使用。

另外提供：

- 遥测字段；
- 状态百分比；
- 物品匹配；
- 字段变化；
- 常量；
- 比较；
- AND / OR / NOT；
- 上升沿 / 持续；
- 冷却；
- A/B 强度与随机强度；
- A/B 持续时间；
- A/B 波形；
- 百分比档位；
- 瞬时变化加强；
- 随机波形；
- 电击输出；
- 禁用软件内置规则；
- 自定义死亡 / 昏迷保护模块；
- 备注。

详细操作见 `md/图形化规则使用说明.md`。

---

# 5. 官方规则与自定义规则完全分域

当前设计明确区分：

### 官方规则域

负责官方规则页面里的规则，包括官方死亡、官方昏迷以及官方死亡/昏迷后的规则级保护逻辑。

### 自定义规则域

负责 `visual_rules.json` 中的图形规则。

自定义规则：

- 不自动继承官方死亡保护；
- 不自动继承官方昏迷保护；
- 不自动继承官方死亡电击；
- 不自动继承官方昏迷电击；
- 不会因为存在自定义死亡图就自动替代官方死亡规则；
- 不会因为存在自定义昏迷图就自动替代官方昏迷规则。

当官方规则没有被禁用时，两套系统可以同时满足条件并分别输出。

共享的只是 DG-LAB 连接、总输出开关、设备 slot、强度硬上限、立即停止、断开设备等底层基础设施。

---

# 6. “禁用软件内置规则”模块

在任意已启用且校验通过的普通规则图中放入：

```text
禁用软件内置规则
```

该模块存在即全局生效，不需要连线。

启用后会关闭 **整个官方自动规则域**：

- 普通官方规则不再向设备输出；
- 官方死亡电击不触发；
- 官方昏迷电击不触发；
- 官方死亡/昏迷后的规则级清输出保护不执行。

图形规则仍可复用现有事件检测器做“只检测、不执行官方输出”的 detector-only 处理。

因此该模块的含义不是“只禁用普通官方规则”，而是：

> **官方规则全部停用，包括官方死亡/昏迷规则和官方死亡/昏迷保护。**

---

# 7. 自定义死亡 / 昏迷保护

图形编辑器提供：

- **未死亡保护（仅自定义）**；
- **未昏迷保护（仅自定义）**；
- **存活且清醒保护（仅自定义）**。

自定义普通规则默认不会因为死亡/昏迷自动停止。

例如：

```text
速度高于阈值 ──────────────┐
                           ├──> 电击输出
存活且清醒保护（仅自定义） ─┘
```

只有用户自己把保护模块接到对应输出，这条自定义规则才会在死亡/昏迷时被保护条件关闭。

如果不接保护模块，自定义规则继续按照自己的条件判断。

---

# 8. 自定义死亡 / 昏迷专用图

死亡 / 昏迷自定义触发仍使用：

- **死亡（专用）**；
- **昏迷（专用）**。

两者必须分别建立独立特殊图。

专用图与普通图结构上隔离：

- 死亡图和昏迷图必须分开；
- 专用图不能混入普通事件；
- 专用图不能混入普通遥测、物品或比较逻辑；
- `禁用软件内置规则` 不能放进专用图；
- 专用图只能包含专用触发、边沿/冷却、输出参数、电击输出和备注。

这里的“专用”只表示 **自定义图内部的结构隔离**，不代表它拥有或覆盖官方死亡/昏迷规则。

如果官方规则没有禁用，官方死亡规则与自定义死亡图可以同时存在；昏迷同理。

---

# 9. 多人联机

多人模式支持：

- 查看队友实时状态；
- 多个 DG-LAB APP / Slot；
- 选择本地主设备；
- 玩家与设备会话级绑定；
- 远程玩家规则输出独立开关。

多人绑定默认不永久保存。

# 10. 软件结构

主要组件：

```text
Coyote
│
├─ Coyote.dll
│  └─ PEAK 游戏数据采集插件
│
├─ backend.py
│  └─ 核心官方规则、DG-LAB 输出与配置
│
├─ ui_qt.py
│  └─ PySide6 桌面界面
│
├─ extended_features.py
│  └─ 恢复、区域、随机波形、渐升等扩展
│
├─ multiplayer_features.py
│  └─ 多人遥测与多设备路由
│
├─ visual_rules.py
│  └─ 图形化规则引擎与节点编辑器
│
├─ visual_rules_hardening.py
│  └─ 检测参数、持续规则、渐升等图形规则加固
│
├─ visual_rules_separation.py
│  └─ 官方规则 / 自定义规则严格分域与自定义保护模块
│
└─ dglab-websocket-server
   └─ DG-LAB V4 通信服务
```

# 11. 安装和使用

1. 在软件中检测或安装 PEAK BepInEx。
2. 安装 / 更新 `Coyote.dll`。
3. 启动 Coyote 并连接 DG-LAB APP。
4. 启动 PEAK。
5. 使用官方规则，或进入 **图形化规则** 创建节点图。
6. 如果要完全接管官方规则，在普通图中放入 **禁用软件内置规则**。
7. 如果希望自定义规则在死亡/昏迷后停止，给对应输出显式加入自定义保护模块。
8. 确认逻辑后再开启左侧 **允许电击输出**。

---

# 12. 输出边界

- 图形规则仍受总输出开关限制；
- 强度经过软件硬上限裁剪；
- `-1` 持续输出由有限片段续播实现；
- 设备断开、关闭总输出、程序退出或点击“立即停止”都可以终止输出；
- 这些属于设备级行为，不是官方死亡/昏迷保护；
- 死亡/昏迷状态下，如果自定义图没有保护条件且自身条件成立，自定义输出不会被官方规则安全锁自动拦截；
- 死亡/昏迷状态下允许执行的自定义规则不会使用带旧 incapacitated 检查的渐升线程，而会直接发送目标强度，避免被官方安全逻辑间接取消。

Coyote 是第三方项目，不是 PEAK、BepInEx 或 DG-LAB 官方产品。
