# Coyote 图形化规则使用说明

## 1. 目标

自定义规则不再要求用户编写 Python。新版使用 **模块 + 端口 + 连线** 的节点图，规则保存在：

```text
Coyote/visual_rules.json
```

程序内部仍然沿用现有 PySide6 / Python 桌面架构，不额外捆绑 Unity 运行时；编辑体验参考 Unity Shader Graph / Unreal Blueprint。

图形规则文件本身是 JSON 数据，不执行用户代码。

---

## 2. 基本操作

1. 打开侧栏 **图形化规则**。
2. 在左侧模块库双击模块。
3. 在中间画布拖动模块排版。
4. 点击源模块右侧输出端口，再点击目标模块左侧输入端口完成连线。
5. 选中模块，在右侧修改属性后点击 **应用属性**。
6. 勾选 **启用当前图**。
7. 点击 **校验并保存**。

快捷操作：

- `Delete / Backspace`：删除选中的模块或连线；
- 鼠标滚轮：缩放画布；
- 框选：同时选择多个模块；
- 一张图可以有多个输出，但死亡/昏迷专用图必须遵守专用隔离规则。

---

## 3. 当前软件规则事件模块

“当前软件全部规则事件”不是写死列表，而是由运行时 `B.RULE_META` 动态生成。

因此当前程序以及已安装扩展注册的规则会自动进入模块库，包括：

### 生命 / 状态

- 血量下降；
- Injury / Hunger / Cold / Poison / Crab / Curse / Drowsy / Weight / Hot / Thorns / Spores / Web / Arrow / Petrify / FlyTrap；
- 血量恢复；
- 体力恢复；
- 状态恢复。

### 动作 / 运动

- 体力消耗；
- 速度低于阈值；
- 速度高于阈值；
- 跳跃；
- 开始攀爬；
- 蹲下。

### 物品

- 拿起手持物；
- 背包装入物品；
- 当前手持匹配物品；
- 背包存在匹配物品；
- 食用 / 消耗物品。

### 区域

- 进入区域；
- 区域停留。

死亡和昏迷不从普通事件模块创建，必须使用专用模块。

---

## 4. 事件模块自己的检测参数

图形规则启用“禁用软件内置规则”后，不应再要求用户回到旧规则页面打开旧规则才能检测事件。

因此当前已有检测参数会跟随对应事件节点：

| 事件节点 | 节点参数 |
|---|---|
| 体力消耗 | `trigger_delta`：至少下降多少 % |
| 速度低于 / 高于阈值 | `speed_threshold` |
| 手持 / 背包 / 状态型物品 | `item_filter` |
| 食用 / 消耗物品 | `item_filter` |
| 血量恢复 / 体力恢复 | `trigger_delta`、`trigger_mode` |
| 状态恢复 | `trigger_delta` |
| 进入区域 | `area_zones` |
| 区域停留 | `area_zones`、`area_dwell_seconds`、`trigger_mode` |

`area_zones` 使用 JSON 数组保存区域，例如：

```json
[
  {
    "name": "山顶篝火",
    "scene": "Level_01",
    "x": 12.5,
    "y": 33.2,
    "z": -8.4,
    "radius": 5.0
  }
]
```

场景留空代表任意场景。

当“禁用软件内置规则”模块生效时，图形引擎会仅在当前遥测处理周期内临时启用图中实际引用的旧检测器，并把上述节点参数覆盖给检测器；设备输出在更前面的图形接管门被拦截，因此这一步是 **只检测，不执行旧规则电击**。处理结束后立即恢复用户原来的内置规则状态和参数。

## 5. 数据 / 条件模块

- **遥测字段**：读取 `hp`、`speed`、`climbing`、`position.x` 等字段；
- **状态百分比**：读取指定异常状态百分比；
- **物品匹配**：判断手持、背包、口袋是否包含指定名称；
- **字段变化**：判断指定遥测字段本包是否发生变化；
- **常量**：数字 / 文本 / 布尔值；
- **比较**：支持 `>`、`>=`、`<`、`<=`、`==`、`!=`、`contains`；
- **AND / OR / NOT**：组合多个条件；
- **上升沿 / 持续**：把持续条件转换为进入边沿、离开边沿或持续状态；
- **冷却**：限制触发频率。

示例：

```text
遥测字段(speed)
        ↓ a
      比较(> 6)
        ↓
    上升沿
        ↓
    电击输出
```

## 6. 输出参数模块

### 强度

强度节点包含：

- `a` / `b`：A/B 基础强度；
- `max_a` / `max_b`：最大强度；
- `random`：是否随机基础强度；
- `min_a` / `max_rand_a`；
- `min_b` / `max_rand_b`；
- `ramp_enabled`：启用现有“从 0 渐升到最终目标强度”功能；
- `ramp_duration_ms`：渐升时间；
- `ramp_steps`：渐升步数。

渐升不是另写一套输出算法，而是复用 `extended_features.py` 已有的强度渐升执行器。最终目标强度仍先经过随机强度、百分比档位、瞬时变化加强和最大值限制。

死亡/昏迷专用输出保持立即执行，不使用普通渐升工作线程，避免普通的 incapacitated 检查反过来取消专用规则。

### 持续时间

- A/B 独立设置；
- `-1` 继续表示条件成立期间续播；
- 底层仍发送有限片段，不直接向设备发送无限时长。

### 波形

- A/B 独立选择当前软件波形库中的波形；
- 可使用内置波形和已加载的自定义波形。

### 百分比档位

连接到输出的 `modifier` 端口，并把需要参与档位判断的百分比数值接入输出 `value`。

多档同时满足时仍沿用 Coyote 原有“只取最严重一档，不累加”的规则。

### 瞬时变化加强

连接到 `modifier`，同时把本次变化量接入输出 `delta`。

多档命中时沿用原有逻辑，只采用命中的最高变化阈值档。

### 随机波形

连接到 `modifier`，从节点指定的波形池随机选择 A/B 波形。

### 电击输出

最终动作节点。可以设置：

- `mode=edge`：条件从 False → True 时触发一次；
- `mode=while/repeat`：条件持续成立时按有效冷却重复；
- `cooldown`：基础冷却。

repeat / while / `-1` 持续图会复用软件的 `continuous_effective_cooldown()`，避免前一段有限输出尚未结束时又无意义叠加下一段。

## 7. 禁用软件内置规则

把 **禁用软件内置规则** 模块放入任意 **已启用、通过校验的普通规则图** 即可生效，不需要连线。

生效后：

- 普通内置规则不会直接向设备输出；
- 图形化规则继续运行；
- 图形规则仍能使用原有事件检测器；
- 原本在旧规则 UI 里关闭的检测器，只要被图中事件节点引用，也会在单包内临时以“只检测”方式运行；
- 检测器参数优先采用事件节点上的参数；
- 本包完成后恢复旧规则的真实启用状态和参数；
- 死亡/昏迷专用规则域不受该模块屏蔽；
- 总输出开关、设备检查、强度硬上限、立即停止仍然有效。

这个模块是全局接管开关：只要任意有效启用图含有它，普通内置自动规则就不再直接输出。

## 8. 死亡 / 昏迷冲突

旧逻辑存在实际冲突：

```text
dead / passedOut 进入状态
        ↓
调用对应规则
        ↓
send_rule_output() 又发现当前已经死亡 / 昏迷
        ↓
安全锁把死亡 / 昏迷规则自己拦截
        ↓
随后清除输出
```

新版拆成两个执行域。

### 普通规则域

角色死亡或昏迷后：

- 普通内置规则停止；
- 普通图形规则停止；
- 手动输出继续受原安全锁限制；
- 旧 Python 自定义脚本不再是活动规则系统；
- 已经存在的普通输出先被清除。

### 死亡 / 昏迷专用规则域

只允许：

- **死亡（专用）**；
- **昏迷（专用）**。

固定执行顺序：

```text
进入死亡 / 昏迷
        ↓
清除之前的普通输出
        ↓
锁定普通规则域
        ↓
检测死亡 / 昏迷边沿
        ↓
执行对应专用图
        ↓
普通规则继续保持锁定
```

---

## 9. 专用规则强制隔离

校验器强制要求：

- 死亡图和昏迷图必须分开；
- 一张特殊图只能有一种专用触发器；
- 专用图不能混入普通规则事件；
- 专用图不能混入遥测字段、状态、物品、普通比较逻辑等其他规则条件；
- **禁用软件内置规则** 不能放进专用图；
- 普通 `trigger` 不能通过填写 `dead` / `passedOut` 冒充专用规则；
- 专用图只允许：专用触发器、边沿/冷却、输出参数、电击输出、备注。

因此“死亡/昏迷触发电击”和“死亡/昏迷后普通规则禁止电击”可以同时成立，不再互相否定。

如果已经启用了对应的图形化专用图，则它拥有该死亡/昏迷边沿，旧 dead/passedOut 规则不会再重复触发；没有专用图时，旧规则仍保留兼容 fallback。

## 10. 规则文件格式

```json
{
  "format": "coyote-visual-rules-v1",
  "version": 1,
  "graphs": [
    {
      "id": "graph_xxx",
      "name": "规则名称",
      "enabled": false,
      "nodes": [],
      "links": []
    }
  ]
}
```

旧 `.py` 文件不会自动删除，便于人工备份或迁移，但新版入口不再加载、执行或创建 Python 自定义规则作为活动规则系统。

---

## 11. 推荐的接管方式

如果希望完全使用节点图管理普通规则：

1. 新建一张普通图；
2. 放入 **禁用软件内置规则**；
3. 再建立实际的普通规则图；
4. 使用“当前软件全部规则事件”或原始遥测节点作为触发；
5. 把检测阈值 / 物品筛选 / 区域参数直接写在对应事件节点；
6. 接条件和输出参数；
7. 校验并保存；
8. 单独建立“死亡（专用）”图；
9. 单独建立“昏迷（专用）”图；
10. 测试日志无误后再开启 **允许电击输出**。

---

## 12. 输出边界

- 左侧 **允许电击输出** 必须开启；
- 强度受 `GUI_INTENSITY_MAX` 限制；
- 波形必须来自当前 Coyote 波形库；
- 普通图在角色死亡/昏迷时不执行；
- **立即停止**、关闭总输出、设备断开、程序退出仍然可以停止输出；
- 专用绕过只对 PEAK 遥测里的 `dead/passedOut` 两个状态开放；
- 普通节点、手动控制和旧脚本不能获得专用绕过权限。
